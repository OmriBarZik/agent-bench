You have Serena in this session: language-server tools that work on symbols (classes, methods, fields) instead of on lines of text. It was added to help you with this task. Use it wherever it fits, starting with your first look inside a source file. Its MCP tools are named `mcp__serena__*` and are already allowed. If they are not in your tool list yet, load them with tool search and read their schemas. Loading them is not using them.

Serena is started on this checkout with a TypeScript language server and Chromium's clangd. It has only read tools: `get_symbols_overview`, `find_symbol`, `find_referencing_symbols`, `find_declaration`, `find_implementations` and `get_diagnostics_for_file`. It has no shell, file, edit or memory tools. Do not switch projects.

**When it beats `grep` in this checkout.** Chromium's web UI is TypeScript and JavaScript, often in long files; its browser and renderer code is C++. A Chromium task has you working out what a class offers, reading the two or three methods that matter, and finding who uses them.

- `get_symbols_overview` with `relative_path` and `depth: 1` lists every class, method and field of a file. That answers "what does this class have?" without reading the file or guessing names to `grep` for.
- `find_symbol` with `name_path_pattern: "Class/method"`, `relative_path` and `include_body: true` returns one method's body and nothing else, so you read forty lines of an 1800-line file instead of all of it.
- `find_referencing_symbols` with `name_path` and `relative_path` returns the real uses of a symbol, each with the symbol it sits in, in the file and in the files that file imports. `grep` for the same name also returns comments, strings and longer names.

**When it does not.** It does not find a file by name or by text across the tree: locate files with `ls` and `grep` through Bash. It has no symbols for `BUILD.gn`, `.gni`, `.idl`, `.mojom`, `.json5` or `.grd` files: read and search those with Read and `grep`. Neither language server has a project for the whole tree: the TypeScript server sees a file and what it imports, and clangd has no index. So `find_referencing_symbols` and `find_implementations` miss uses in files that import the symbol's file (for a method that only another file calls, it finds none): find callers in other files with `grep`. Many TypeScript directories in the checkout have no `tsconfig.json` next to their sources, so `get_diagnostics_for_file` there reports a missing `chrome://resources/...` import and the null-check errors that follow from it on lines nobody changed. The first Serena call waits about 15 seconds while Serena scans the checkout, and each `find_referencing_symbols`, `find_declaration`, `find_implementations` or `get_diagnostics_for_file` call rescans it first, so expect 15 to 20 seconds per call. If a call fails or times out, use Read and `grep` for that question, go on with the task, and say so in your final message.

**Start with it.** Before your first search, decide what you will use Serena for in this task and say so in one sentence. Make your first code search inside a source file with Serena: when `ls` or `grep` has given you the file, call `get_symbols_overview` on it instead of reading it or grepping it for names. You must use Serena's language-server tools, named `mcp__serena__*`, for every question about what a file defines or a symbol's body, and for a symbol's references inside its own file and the files it imports. The baseline rule that sends a search to `grep` through Bash is the fallback for the searches Serena cannot do. It is not where a search starts. When Serena cannot answer, use `grep` for that one question, and come back to Serena for the next one that fits.

**Three questions a Chromium task asks, and how Serena answers them.**

- What can a web UI dialog element do, and who cancels it? `get_symbols_overview` with `relative_path: "ui/webui/resources/cr_elements/cr_dialog/cr_dialog.ts"` and `depth: 1`, then `find_symbol` with `name_path_pattern: "CrDialogElement/cancel"`, the same `relative_path` and `include_body: true`, then `grep -rn 'cancel()' ui/webui/resources/cr_elements` for its callers in other files.
- How does the preference registry register a boolean preference? `find_symbol` with `name_path_pattern: "PrefRegistrySimple/RegisterBooleanPref"`, `relative_path: "components/prefs"` and `include_body: true` reads the one method without the rest of the file.
- What does the preference service offer in C++? `get_symbols_overview` with `relative_path: "components/prefs/pref_service.h"` and `depth: 1` lists the class; `find_symbol` reads the one method you need. Which build target compiles a file is a text question: use `grep` for it.

**How to call it.** Pass `relative_path` on every call, a file or a directory: `find_symbol` without one walks the whole checkout and does not finish in useful time. `find_symbol` takes a name path such as `Class/method`, or a bare name. Line numbers in Serena's results are 0-based.

**Rules.** Serena cannot edit: Edit and Write are the way to change a file, and the baseline rule about Edit and Write applies to the shell: do not create or edit files from Bash. The shell stays at the checkout root. Do not use `cd`. The baseline shell rules still apply.
