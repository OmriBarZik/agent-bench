You are working in a Chromium source checkout. Chrome has an offline game where a T-Rex dinosaur runs, jumps and ducks over obstacles. Make the dinosaur play the game by itself, driven by a decision model that is built into the browser.

The model is a small decision model in the style of a "System One" model (like TypeSafe's Jev): structured state goes in and one typed decision comes out, together with a probability for each possible decision. Here the input is the game state (at least the dinosaur's position and whether it is jumping or ducking, the type, distance, width, height and y-position of the upcoming obstacles, and the current speed). The output is exactly one of three decisions: `jump`, `duck` or `nothing`, with a probability for each. It must never return anything outside those three.

Everything must work offline. The dinosaur game is what Chrome shows when there is no network, so the model may not call a server, download weights at runtime, or depend on any optional component that has to be fetched. The model and its weights, parameters or rules must be compiled or packaged into Chrome itself and built as part of the product with the existing build targets.

Expose the model to JavaScript as a built-in AI API. Before designing it, find out how Chromium already exposes built-in AI to web pages. If there is already a built-in AI object or API family, extend it or add the new API alongside it the same way the existing ones are defined, wired and gated, instead of inventing a separate mechanism. The API must be reachable from the page that hosts the dinosaur game.

Then change the dinosaur game to use this new JavaScript API: on every frame (or at a fixed rate) it reads the real game state, asks the model for a decision, and applies it through the game's existing jump and duck code paths, with no keyboard or touch input from the user. It must restart by itself after a crash. Auto-play must be switchable on and off and off by default, and the new API must be behind a feature flag. When the API is not available, the game must behave exactly as it does today.

Follow the data end to end: from the game's state in JavaScript, through the API binding, to the model and back to the dinosaur's action. Choose where each piece lives yourself, following how Chromium structures similar code. Do not run a full Chromium build; make the change so it would build with the existing targets.
